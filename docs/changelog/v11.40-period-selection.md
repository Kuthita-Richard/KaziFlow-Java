# v11.40 — Period selection for exports (R1, step A)

## Added
- `utils/DateRangePicker` — the one inline period control: preset box (today … last year, all time, custom dates), two date fields that are editable only for "Custom dates…", and a caption that always says which dates are meant ("1 Nov 2026 – 30 Nov 2026 (30 days)") or why the choice is invalid (red). `getRange()` is null while invalid; a custom range may leave one end empty ("From …"). "Today" is injectable. R2's analytics pages embed this same control.
- Dates are shown day-first ("4 Nov 2026") and typed dates are read day-first (`04/11/2026`, `4-11-2026`, `4 Nov 2026`, ISO); 11/10/2026 is 11 October, never 10 November; impossible dates (31/02/2026) are rejected.
- `utils/DateRangeDialog.ask(owner, reportName)` — "Which period should the export cover?" with Export disabled while the choice is invalid (default: All time, so nothing changes for anyone who just clicks through).
- `ReportExportService.exportCSV(type)` now asks for a period when `isPeriodBased(type)` (Sales, Expenses, Purchases, Finance Summary), then asks where to save; cancelling the period dialog exports nothing. Inventory and Employees (no dates in the data) do not ask. All 13 call sites in the views go through this one method, so no view changed. `askPeriod` and `chooseFile` are overridable seams for tests.

## Verified
`tools/checks/DateRangePickerCheck` (50 assertions; mutation-tested 12/12): every preset on a fixed Wednesday, across a year boundary (week spanning New Year, last month = December, last quarter) and in a leap year (last month = 1–29 Feb); `previousPeriod`/`sameLastYear`; the SQL filter against a real SQLite (a month includes its first and last second, ALL adds no condition, open-ended ranges); the picker's state machine (preset → custom, invalid states, single day, open-ended, listeners); the dialog (Export enable/disable, result, cancel); the export flow for every report type (asks iff period-based; the file name carries the period; cancel never opens the file chooser); day-first parsing. The dialog was rendered under Xvfb and looked at in three states. Full regression: 19 suites + the user-management renderer, 0 failures; JUnit 240 tests, the same 25 pre-existing failures.

## Not changed
`ReportsView`'s own header controls are step B.
