# v11.34 — Trust fixes and honest exports (release R1)

## Fixed
- **Reports pie chart** invented Cement/Steel/Paints/Hardware slices when the query was empty. Now: real data (`LEFT JOIN`, so products with no category count as "Uncategorised"), top 5 categories + "Other", and an honest empty state ("No stock on hand yet…").
- **Login screen** claimed "Trusted by 500+ businesses in Nairobi & Mombasa" and offered a "Sign in with Google" button with no OAuth client behind it. Both removed (with the divider); it now shows only the tagline and the Tihems lineage.
- **Exports rebuilt** (`ReportExportService`, new `utils/DateRange`):
  - optional period (`exportCSV(type, DateRange)`; `exportCSV(type)` = all time); the filename carries the period;
  - no 1,000-row cap (the Sales export was `SELECT * … LIMIT 1000`, silently partial);
  - TOTAL rows are computed from the rows actually exported (the old "Total Revenue" footer printed **this week's** revenue under a label for other rows);
  - UTF-8 with BOM, `Locale.ROOT` numbers, CSV-injection defence on text cells;
  - **Finance Summary was a fabricated P&L** (COGS = 60% of expenses, payroll 40%, rent 15%…). Rebuilt from `sales`, `sale_items.cost_price` and `expenses`, with printed definitions and data-quality warnings;
  - **Purchases export had always failed**: it read a column that does not exist (`tax_amount`; the real column is `vat_amount`). Found because the rewrite checks every column used by the exports against the schema.

## Verified
`TrustGuardTest` + `BrandGuardTest` (7 JUnit tests); `tools/checks/ReportExportCheck` (30 assertions).

## Not done (still R1 scope)
