# v11.1 — Stock-Take Module & Real Quotation→Sale Conversion

## Stock-take / physical inventory count (Phase 10E, item 2/6)
- **Where:** new `src/main/java/com/kaziflow/dao/StockTakeDAO.java`, new `src/main/java/com/kaziflow/views/StockTakeView.java`, `src/main/java/com/kaziflow/views/InventoryView.java`, `src/main/java/com/kaziflow/App.java`
- New tables: `stock_takes`, `stock_take_items`.
- Flow: **Start New Count** snapshots every product's current system quantity → counter fills in counted quantities per row (auto-saved via `saveCountedQty` as they go) → **Complete & Apply** updates live stock via `ProductDAO.updateStock()` to match the count and logs a proper `adjustment` row per changed product in `stock_movements`, with live variance shown per row. Uncounted rows are skipped, not zeroed.
- Wired in as a "📋 Stock Take" button on the Inventory toolbar. Registered at startup (`App.java`) alongside the other lazy-table DAOs.

## Quotation → Sale conversion — found it was a stub, made it real (Phase 10E, item 3/6)
- **Where:** `src/main/java/com/kaziflow/views/QuotationView.java`
- **Problem found:** The existing "Convert to Sale" button only changed the quotation's `status` to `converted` and told the user to manually go complete the sale in POS. Not an actual conversion.
- **Fix:** Now creates a real, completed `Sale` with real `sale_items`, reduces stock the same way a POS sale does, and triggers ETIMS serial generation.
- **Edge case handled:** `sale_items.product_id` is `NOT NULL`, but a quotation can have free-text line items with no linked product (e.g. a custom service charge). Those are now clearly called out to the user and excluded from the generated sale rather than crashing on a foreign-key violation or being silently dropped.
