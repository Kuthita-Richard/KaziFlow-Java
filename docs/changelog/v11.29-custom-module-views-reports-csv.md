# v11.29 — Custom modules, "Access-style" layer: validation rules, saved views & reports, subforms, CSV

Follows the v11.28 engine. Rationale: data could go in but answers couldn't come out; related records needed tab-hopping; and small businesses start from Excel.

## What was built (package `com.kaziflow.custom`)
- **Validation rules** — per-field min/max (numbers bound the value; text bounds its length) with an optional custom message; enforced on create, update and import; additive migration for older databases; inputs added to the builder's field dialog.
- **Saved views & reports** — `CustomQueryService` (conditions, sort, group by field / month / year, totals sum·average·smallest·largest, grand totals, relative date tokens) and `CustomViewEditorDialog` (all dropdowns, nothing typed). Views are saved per record type and shared; each tab has a views dropdown ("All records", saved views, "(customized)"), a grouped-report display with a TOTAL row, and totals that cover ALL matching records.
- **Subforms** — `CustomRecordForm`: opening a record shows every record type that links to it, filtered to that record, with add/edit/delete in place; parent link pre-filled and locked; buttons follow the child module's access. (The generated form was extracted from the list screen so both use it.)
- **CSV** — `CustomCsv`: export of lists and reports (UTF-8 + BOM; formula-injection defused); import with a preview step (per-row problems, spreadsheet row numbers, nothing written), then a single all-or-nothing transaction for the valid rows. Handles `;`/`,`, `dd/mm/yyyy`, `KES 1,200`, yes/no, link/choice matching by text.
- **Printable report page** — `CustomReportHtml`: self-contained print-styled HTML opened via `Desktop` (same approach as `ReceiptPrinter`); all values escaped.

## Performance (measured, 20,000 records) and the two inefficiencies it exposed
Grouped report ~200 ms, filtered list ~200 ms, plain list ~65 ms, bulk create ~1.2 s. The first run showed bulk create at **24 s** and lists at 1.2–1.5 s per 1,000 rows: the schema check ran on every connection, and each row re-read its field definitions and re-verified link targets on a new connection. Fixed (schema check once per process; fields read once per query; link existence cached per batch) — **every existing custom-module list got ~20× faster**.
