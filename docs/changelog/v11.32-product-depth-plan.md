# v11.32 — Product depth plan (research, measurement, plan; no application code changed)

Requested because much of the product is shallow — analytics most visibly.

## What was done
- **Measured** every module (`tools/depth_audit.py`, reproducible): lines of screen code, tabs, charts, tables, dialogs, filters, data-access breadth. **Correction to an earlier statement:** the tool's first version also counted `new PieChart.Data(…)` rows as charts, which inflated the totals (I had said 9 charts; the real figure is **4 in the whole product**; Reports has **2**, not 7). The regex now matches constructors only.
- **Benchmarked** against published documentation of comparable products: Zoho Inventory/Books, Lightspeed, Square, PayPal Zettle, Odoo, QuickBooks, Sage; and Kenyan eTIMS guidance (KRA, KPMG and practitioner summaries).
- **Verified what data already exists** for each proposed report (schema checks): most analytics needs no new data. Genuine gaps: tax class per product/line, eTIMS and supplier invoice numbers on purchases/expenses, VAT split on expenses, a shift/cash-up record, leave types/entitlements.
- **Wrote `docs/design/product-depth-plan.md`:** a D0–D4 depth scale, a per-module target, the analytics suite page by page (8 pages, ~35 tabs/reports, each marked ✅ data exists / ⚠ small addition / ❌ new feature), a 6-release sequence, and the decisions needed.

## Findings (documented, not fixed — fixing is release R1 of the plan)
1. **Receipts print an invented "ETIMS Serial: KRA-…"** — a local counter formatted like a KRA serial, never sent to KRA. The most serious item found in the whole audit.
2. Reports pie chart shows invented data when the query is empty.
3. The six "reports" are raw table dumps; "Sales Report" silently exports only the newest 1,000 sales.
4. Finance's "Chart of Accounts" is a derived summary, not a ledger.
5. (Already recorded) numbering race, payment-method `CHECK` constraint, false login claims, AI prompt carrying the default admin login, hardcoded licence signing secret.

Plan statements about line counts and database columns were each checked against `depth_audit.py` output and the schema; one column name that was wrong in the draft (`products.category`; the real link is `products.category_id → categories.name`) was corrected before commit.
