# v11.33 — Receipts no longer print an invented KRA serial (release R1, item 1)

## Problem (found in the v11.32 audit)
`ETIMSService.generateSerial` returned a locally incremented number formatted `KRA-<year>-<seq>` (status `local`, never sent to KRA) and `ReceiptPrinter` printed it as **"ETIMS Serial"**. A tax-compliance number that KRA never issued — the most serious item in the audit.

## What changed
- `ETIMSService`: the local counter is now labelled `LOCAL-<year>-<sequence>`; `isConnected()` returns `false` (there is no KRA connection until onboarding is done); `getTransmittedSerial(saleId)` returns a number **only** when KRA actually received that invoice. Legacy rows whose number looked like a KRA serial are migrated to `LOCAL-…`, so reprinted or looked-up old receipts no longer show one.
- `ReceiptPrinter`: prints an eTIMS number only if `getTransmittedSerial` has one.
- `SettingsView`, `FinanceView`: wording no longer implies a live KRA connection.

## Verified
`tools/checks/EtimsHonestyCheck` — 13 assertions. `TrustGuardTest` bans the phrases `ETIMS Serial`, `KRA-%s` and a hardcoded `"KRA-` in any string literal.

## Still open (external dependency)
Real eTIMS submission needs KRA onboarding (OSCU/VSCU, credentials, certification) — release R4, and the owner must start it.
