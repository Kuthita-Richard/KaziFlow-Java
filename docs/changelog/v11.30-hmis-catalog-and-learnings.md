# v11.30 — HMIS sample company: verified, captured as data, and analysed

Documentation and tooling only; no application code changed.

## What was done
- **Verified** `HMIS_Feature_Reference.md` against all 47 screenshots by OCR: accurate, every real word present. Two phrase-level omissions fixed (Pharmacy → *Procedures Report*; Patient Invoices → *Miscellaneous Income Invoices*). Added a note that the system shows NHIF (replaced by SHIF in Oct 2024; KaziFlow already uses SHIF).
- **Captured the menu as data:** `docs/reference/hmis_menu_catalog.tsv` — 405 entries in 50 modules, each tagged by kind (register / list / transaction / workflow / report / setting / queue).
- **Measured it:** `tools/hmis_catalog_stats.py` (reproducible). Headline: 58% of entries are reports or lists; 41% are mechanical register/view CRUD; 75% are not hospital-specific; 8% are generic workflow states (a first draft of this figure said 11% — it wrongly counted hospital admit/discharge entries and was corrected before being written down).
- **Compared with KaziFlow** area by area, every row checked against the schema/code, and wrote `docs/design/hmis-learnings.md` with 11 lessons and a prioritised plan.

## Findings in KaziFlow (documented, not fixed)
- Invoice numbers are `COUNT(*)+1` read-then-write: a `SQLITE_BUSY_SNAPSHOT` risk in LAN checkout.
- Payment methods are a `CHECK` constraint on `sales` — adding one needs a migration.
- The Finance "Chart of Accounts" is a derived summary, `accounts.balance` is never written, there is no ledger.
- `SessionManager.getBusinessSetting()` is a dead stub.
