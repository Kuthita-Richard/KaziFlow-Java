## "Are the modules just the same, or am I missing something?" — verified, not user error

Checked the actual data rather than assuming: **several profiles genuinely share an identical module list today.** Confirmed by direct inspection — Supermarket, Liquor Shop, and Butchery all reduce to exactly the same four modules once the display's common-module filter is applied ("Inventory, Batch/Expiry, Sales & POS, Purchases"), because there's no separate backend module per retail vertical yet — they're all just generic inventory + batch tracking under the hood. This is a real characteristic of how the app is currently built, not a rendering bug and not something the person was missing.

**What genuinely does differ, checked per-profile:** terminology. Supermarket calls things "Item"/"Distributor"; Butchery calls them "Cut/Item"/"Meat Type" — real, meaningful customization. Liquor Shop, however, has zero terminology override at all (`Map.of()`) — it is, today, literally identical to a generic retail profile in every respect except its icon and name.

**Fix:** rather than fabricate a difference that doesn't exist, each card now shows a second line — "Calls things: ..." — built from that profile's actual `terminology` map, only when it has one (19 of 22 profiles do). This gives genuine, honest differentiation for the large majority of profiles instead of implying module differences that aren't real. Profiles with no terminology override (like Liquor Shop) simply don't get an extra line — no fake distinction added.

## Left as an open question, not fixed here

Whether the identically-featured profiles (Supermarket/Liquor Shop/Butchery, and likely a few others) should eventually get distinct backend modules is a real product decision, not something to guess at and build unprompted. Flagging it here as a known gap rather than silently deciding either way.
