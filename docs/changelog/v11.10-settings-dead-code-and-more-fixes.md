# v11.10 — Critical Fix: Six Settings Dialogs Were Dead Code

Continuing "check everything and fix." This pass found a bug my balance-checker scripts structurally cannot detect — a **misplaced** brace rather than a missing one, where total counts stay equal but nesting is wrong.

## Critical bug: most of Settings' special click handlers never fired

- **Where:** `src/main/java/com/kaziflow/views/SettingsView.java`, `buildModuleCard()`
- **Problem:** `if (title.equals("Users & Access")) {` never actually closed before the next six title checks — they were all nested *inside* it instead of being sibling `if` statements. Since a card's title can never simultaneously equal "Users & Access" and, say, "Currency", every one of those inner checks was unreachable dead code:
  - **Roles & Perms**, **Tax Settings**, and **Audit Trail** — these predate this session entirely (original v9 code) and **have never worked**, in any version shipped so far.
  - **Currency**, **Email Receipts**, and **Network / Multi-Computer** — the three dialogs built in v11.3 and v11.7 this session, which I built, manually reviewed, and even individually balance-checked — and every one of those checks passed, because the brace *count* was correct throughout; only the *nesting* was wrong. This is exactly the class of bug that a "count `{` vs `}`" script cannot catch, and it's why this needed an actual read-through of the logic, not another automated pass.
- **Fix:** Closed the `Users & Access` block immediately after its own handler, making all seven checks (`Users & Access`, `Roles & Perms`, `Tax Settings`, `Currency`, `Email Receipts`, `Network / Multi-Computer`, `Audit Trail`) proper independent siblings. Total brace count is unchanged (verified) — only the nesting moved. Read through the rest of `buildModuleCard()` afterward (`Data Management`, `M-Pesa`, `SMS`, `System Modules`, `AI Assistant`, `Language`, `DB Encryption`, `License`) to confirm no further instances of the same mistake — none found.

## Other fixes from this pass

**Stale Variance column in Stock Take** — `src/main/java/com/kaziflow/views/StockTakeView.java`. Entering a counted quantity saved correctly to the database, but the in-memory row array (which the Variance column reads from) was never updated, so the column stayed blank/stale until the whole screen was reopened. Fixed: the counted-qty cell now updates the in-memory row and calls `table.refresh()` right after a successful save.

**Chart range guard rail** — `src/main/java/com/kaziflow/views/DashboardView.java`. The date-range picker had no upper bound; an accidental multi-year selection would render one bar per day. Added a 366-day cap with a clear error message.

**Hash-chain verifier false positives on legacy rows** — `src/main/java/com/kaziflow/services/AuditLog.java`. `verifyChainIntegrity()` didn't reset its "expected previous hash" tracking after skipping a pre-migration row with no hash, so it would flag every row *after* a legacy row as a broken chain link — a false alarm, not a real tamper detection, and a realistic scenario since this app's `audit_log` table already had historical rows before the hash-chain feature (v11.4) was added. Fixed to match `fetchLastHash()`'s actual fallback behavior (resets to `"GENESIS"` after any null-hash row).

**Quotation quantity precision loss** — `src/main/java/com/kaziflow/dao/QuotationDAO.java`. `getItems()` formatted quantity with `%.0f` (whole numbers only) while every other numeric field used proper decimal formatting. Any quotation with a fractional quantity (e.g., 2.5 kg) silently rounded — both in the UI display and, more importantly, in the new quotation→sale conversion (v11.1), which reads from this same formatted string. Fixed to `%.2f`, matching the other fields. Pre-existing code, not introduced this session, but inherited and made more consequential by the new conversion feature since it now affects real stock-reducing sales, not just a printed quote.

**Customer name / redemption cap consistency** — see v11.9 (same pass, documented separately since it was found first).
