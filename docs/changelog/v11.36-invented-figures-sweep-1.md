# v11.36 — Invented-figures sweep, part 1 (money screens) and the demo-expense duplication

## Fixed
- **Reports** KPI cards: no more fallbacks (4.2M / 1.8M / 850k / 12.5M), the invented "42% margin", "+12% vs last month", "Operations & Payroll" or "1,240 SKUs". Each card shows the real value (0 shows 0) and a caption that is computed (month name, "x% of revenue", real active-product count). "TOTAL REVENUE" is now "REVENUE" because it is this month's. The pie subtitle says what the pie is (stock at cost, by category).
- **Finance → Expenses** cards: real total / this month / last-12-month average / top category with its real share (`ExpenseStats`, `TopShare`); the month label is computed (`DateRange.monthLabel`), not typed. **Finance → VAT** "VAT Rate 16%" now reads the configured rate (`VATConfig`) or says "Off".
- **Expenses screen:** "Top Category: Payroll" and "Avg per Month: —" are computed; the **"By Category — this month's breakdown" panel was a hardcoded table** (Payroll 320,000 58%, Rent 85,000 15%…) shown beside a "This Month KES 0" card; it is now built from this month's expenses.
- **Sales history** "Top Payment Method: Cash, 56% of sales" is computed from this month's sales (`TopShare`). **Inventory** "+2.4% vs last month" removed (caption: "At selling price", which is what `ProductDAO.getTotalStockValue` computes).
- **Demo expenses were re-inserted on EVERY app launch.** `DatabaseManager.seedDefaultData` ran an unconditional `INSERT OR IGNORE` of 8 demo expenses (rent, payroll, utilities…); `expenses` has no unique key, so each launch added 8 more (3 launches → 24 rows, 562,500 each time). Now seeded once per database (flag `demo_expenses_seeded` in `settings`), never into a table that already has rows, never re-created after the owner deletes them.

## Verified
`tools/checks/InventedFiguresCheck` (38 assertions): pure `TopShare` / `ExpenseStats` on fixed dates; the real screens rendered with an EMPTY database (no invented figure may appear, banned strings are rendered through `KESFormatter` so they cannot drift) and with seeded data (the figures are the ones the data produces); seeding idempotency. Mutation-tested: 8 of 8 re-introduced bugs caught (one was missed at first — the banned-string list had the wrong spelling of 850,000 — and the check was fixed). `TrustGuardTest` gained 10 phrases. Full regression: 15 check suites, 0 failures; JUnit 240 tests, the same 25 pre-existing failures.
