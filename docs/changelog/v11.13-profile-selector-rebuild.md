# v11.13 — First-Run Profile Selector: Fixed Selection Bug, Smaller Cards, Grouped by Category, Shows Included Modules

Reported: the industry-selection boxes shown on first launch "somehow not connected to where they're expected to select," plus requests for smaller cards, sensible ordering, and each card showing what modules it includes.

## The real bug behind "not connected to where they're expected to select"

- **Where:** `src/main/java/com/kaziflow/modules/ProfileSelector.java`
- **Problem:** Each card was a JavaFX `ToggleButton` inside a `ToggleGroup`. This is a well-known JavaFX footgun: clicking the *already-selected* toggle in a group deselects it, leaving the group with nothing selected at all — `ToggleButton`/`ToggleGroup` don't enforce "always exactly one selected" on their own. Worse, the code only updated the tracked `selected` field when a toggle became selected; when everything became deselected (`nw == null`), nothing happened — so the internal state could silently go stale and disagree with what was visually highlighted (or not highlighted) on screen. A user clicking the pre-selected default card, or clicking around a couple of times, could easily end up in a state where nothing looked selected, and what would actually get saved on "Continue" was disconnected from what they saw.
- **Fix:** Rebuilt with a manually-managed single-selection model instead of `ToggleButton`/`ToggleGroup`. Every card is a plain clickable `VBox`; clicking one always selects it and restyles all cards from a single source of truth (`highlightSelectedCard()`). There is no interaction path — click the selected one again, click rapidly, anything — that can leave zero cards selected or let the internal state disagree with the display.

## Requested UX improvements

- **Smaller cards** — reduced from 220×120px with 16px padding down to 168×88px with 10px padding; smaller fonts throughout.
- **Grouped and ordered properly** — the 22 industry profiles are no longer a flat list in raw enum declaration order. Grouped into 7 categories with headers: Retail & Trade, Food & Hospitality, Health & Veterinary, Automotive & Repair, Personal Care & Fitness, Financial Groups, Other.
- **Each card shows its included modules** — e.g. General Retail/Hardware now shows "Includes: Inventory, Sales & POS, Purchases, HR +3 more". Built from each profile's real `moduleIds` list (not a hand-maintained duplicate), filtered to skip the 3 universal modules every profile has (Dashboard, Settings, Help) since those don't help distinguish one business type from another, capped at 4 shown with a "+N more" tail so cards stay compact.

## Not yet done

This screen (and the equivalent "Change Industry Profile" access point in Settings, if one calls into the same `ProfileSelector` class) should now behave correctly, but hasn't been runtime-verified against real JavaFX — same limitation as every other UI file this session, since JavaFX still isn't compilable in this sandbox. Field names, method signatures (`IndustryProfile.displayName/icon/moduleIds`, `ModuleRegistry.setProfile()`), and import coverage were all individually cross-checked against their actual source rather than assumed.
