# v11.27 — Positions & Access: editor, enforcement, real data on the admin screens

Tasks 2, 3 and 4 of the v11.25 hand-off, plus the custom-modules feasibility study.

## Task 2 — Positions & Access editor (`views/PositionsAccessView.java`)
Replaces the old read-only "Roles & Perms" screen (deleted). Create / edit / delete Positions; "Also includes" (inheritance, with loop detection); a Read/Create/Write/Delete matrix whose **module rows come live from `ModuleRegistry.getAllAvailableModules()`** (modules disabled for this business are flagged, grants for modules the app no longer offers are shown rather than hidden); Create/Write/Delete require Read; "Inherited" column; special permissions rendered from the `permission_actions` **table** (+ "Add action"); unsaved-changes guard; Administrator shown locked.

## Task 3 — Enforcement
- **Seeding + legacy migration (`PermissionGroupSetup`) — this piece of the design had never been built;** on a real install `permission_groups` was empty. Includes a break-glass self-heal (an administrator is restored at startup if none exists).
- **Lockout safety (`PermissionAdminService`):** every mutation is one transaction with an "≥1 active administrator-equivalent remains" post-condition; Administrator can't be renamed/deleted; a Position implying Administrator counts as admin-equivalent (checker and guard share `PermissionResolver`).
- **`ModuleRegistry`:** sidebar filtered at *read time* per user (not in `loadModules()`, which runs once before login); `isAccessible`, `getFirstAccessibleModuleId`, `registerModule` (admin-built modules appear in the editor immediately), `Module.alwaysAccessible()` (Help), `Module.isUserDefined()`.
- **`SceneManager.navigateTo()`** gate (shortcuts/quick-links can't bypass the sidebar), `ACCESS_DENIED` audit event, landing on first permitted module, "No access assigned yet" page.
- **`UserManagementView`:** single role dropdown → multi-select Positions; position filter from the DB; validation before the dialog closes; can't deactivate yourself; lockout errors surfaced.
- **Special actions enforced** (each seeded action has a real check): `view_cost_price` (Inventory cost label + cost field, never overwritten on save), `apply_discount` (loyalty-points redemption), `void_sale` (returns/refunds). Via `PermissionGuard`.
- **Live re-validation:** `permissions_epoch` — edits reach logged-in users / other PCs within ~3 s.
- `SessionManager.hasPermission()` (zero callers) now delegates to the real engine and is deprecated; login/logout invalidate the permission cache.

## Task 4 — Settings & Administration: real data, not invented data
- **Users screen** had fabricated content — made-up role counts (12/4/2/6), a fake activity feed ("Mercy promoted to Manager", "Suspicious login for Sarah W."), "Licenses x/30", "+2 this month", Last Login always "—". Replaced with real counts, the real audit feed, real last login.
- **Settings cards:** "12 Active Users", "5 Roles Defined", M-Pesa "Connected", "VAT: 16%" (also hardcoded in the description), "Last Backup: 2h" were all invented → real values (`VATConfig`, `BackupService`, settings, `UserDAO`, positions).
- **Per-card Enabled/Disabled toggles removed:** they saved `module_<x>_enabled`, which nothing read, and they hid each card's status text. Real on/off remains Settings → System Modules.
- **M-Pesa consumer secret + passkey and Africa's Talking API key** were plain visible `TextField`s → masked, with the reveal toggle.
- Settings cards disabled unless the user has Write on the Settings module.
- **Bug fixes found on the way:** `BackupService.getLastBackupTime()` used UTC (3 h off for Kenya); **`AuditLog` silently dropped every event with nobody signed in** (`user_id = 0` violated the foreign key) — now NULL, so failed logins are recorded; new audit events `LOGIN_FAILED`, `ACCESS_DENIED`, `POSITION_*`, `USER_ACCESS_CHANGED`, `PASSWORD_CHANGED`.
