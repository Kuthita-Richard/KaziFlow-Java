# v11.31 — Brand identity (Tihems → Tihems Software → product) and product pictures

## Brand identity as data
- **Hierarchy:** Tihems (the group, many niches) → Tihems Software (its software department, owner of the product) → the product ("KaziFlow ERP", interim). One logo set shared by all three; only the names differ by level.
- **`brand.properties` + `Brand`** are the single source of every name. ~45 hardcoded user-visible strings (window titles, login, sidebar, Help, Settings, receipts, report exports, email defaults, the AI assistant's persona, network error messages, licence/encryption file headers) now read from it. Optional per-install `brand-override.properties` for white-labelling.
- **Assets:** the four supplied JPEGs (kept in `docs/brand/source/`) were converted to transparent PNGs; the app icon was **rebuilt crisply** from the 1254 px master (the supplied icon is only ~168 px) to match the supplied design; full icon set for the window, installers (.ico / .iconset / .png — replacing the old green "K"), and favicons. Reproducible: `python3 tools/build_brand_assets.py`. The mark shows on the login panel and sidebar; every window gets the icon through one global hook; printable report pages carry a favicon and a "Powered by … · Tihems Software · a Tihems company" footer.
- **Installer publisher/copyright** now "Tihems Software". The EULA's legal text is untouched (it names an individual; which legal entity should be licensor is a decision for the owner).
- **`AppPaths`** centralises the data folder / database file path that was duplicated in 13 places. It deliberately does NOT follow the brand, so a rename can never orphan existing installs' data.
- **`BrandGuardTest`** (JUnit, 5 tests; mutation-tested) fails the build if a product name is hardcoded in Java, if invented names ("KaziFlow Systems Ltd", "KaziFlow Technologies Ltd") or the stale "v2.4.0" return, if installers drift from `brand.properties`, or if a brand asset is missing/opaque.
- **Fixes found on the way:** Help and Settings showed a made-up "v2.4.0" (now the real version from one constant); login/Help invented two different company names; the debtor SMS was signed with the *software* name instead of the shop's.

## Product pictures
`products.image_path` existed but nothing read or wrote it. Now: pick a file (or drag one onto the preview) in the add/edit product dialog; the photo shows in the inventory table (coloured letter avatar when there is none) and on the POS product cards. `ImageProcessor` validates the file, refuses decompression bombs before decoding, applies phone-photo EXIF rotation, flattens transparency and re-encodes (a 12-megapixel photo becomes ~50 KB). Stored as base64 text in `product_images` (the LAN protocol cannot carry BLOBs). Batched thumbnail prefetch: 450 products in 12 ms.
