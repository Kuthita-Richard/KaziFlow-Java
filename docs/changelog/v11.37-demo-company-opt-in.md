# v11.37 — Demo data is opt-in: "Demo Company"

Owner decision (v11.36 review): demo data must not ship in new databases; it is loaded only on request.

## Problem
`DatabaseManager.seedDefaultData` inserted sample suppliers (one owing 450,000), employees, products, **transactions** (a 500,000 "Opening balance" and 1.4M of "Sales Revenue") and expenses into every real database, so every report, VAT and finance figure included them. `transactions` and `expenses` have no unique key, so they were inserted again on every launch (3 launches → 30 transactions, 4.36M of fake income, 24 expenses).

## What changed
- New databases start with the structural defaults only (roles, admin user, categories, departments, chart of accounts, settings) and **no** suppliers, employees, products, transactions or expenses. The v11.36 "seed once" flag is gone (nothing is seeded).
- `services/DemoDataService`: `load()`, `remove()`, `countPresent()`, `isPresent()`. A demo row is identified by its natural identity (supplier code+name, employee number+name, SKU+name, transaction reference+description, expense description+category+amount), so loading is idempotent and removal also cleans databases created by earlier versions, including their duplicated copies. Products link to demo suppliers by supplier **code**, and to categories/departments/accounts only if they exist.
- Removal never force-deletes: a demo product used by a real sale, purchase or stock movement (a real foreign key, NO ACTION) is kept together with its supplier, and the result says what was kept. Product images and batches of a removed demo product go with it (ON DELETE CASCADE). Load and remove are written to the audit log.
- Settings → **Demo Company** (needs Write access to Settings): shows "Not loaded" / "Demo data loaded", and offers Load or Remove with a plain description of what happens.

## Verified
`tools/checks/DemoCompanyCheck` (20 assertions; mutation-tested 5/5): a new database is empty and restarts add nothing; load is idempotent and survives an app restart; supplier links by code even when a real supplier took row id 1; remove leaves the owner's own rows, keeps rows a real sale uses, matches exactly (an expense with the same words but another amount is not deleted) and cleans legacy duplicates. `tools/checks/EmptyDatabaseSmokeCheck`: 32 screens build on an empty database (5 skipped because they need constructor arguments: AIAssistantView, BranchView, LicenseActivationView, NewPurchaseView, StockTakeView); mutation-tested. Full regression: 17 check suites, 0 failures; JUnit 240 tests, the same 25 pre-existing failures.

## Existing installations
Nothing is deleted automatically. A database that already holds the old demo rows keeps them until the owner uses Settings → Demo Company → Remove demo data.
