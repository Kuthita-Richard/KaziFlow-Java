# v11.8 — Real Compile Errors Found via Actual `mvn javafx:run` — Fixed

This is the first time this project was compiled with real Maven Central access and the actual JavaFX SDK (on your machine, not this sandbox). All prior verification (v10–v11.7) was either manual code review or, for the network layer only, compiled/runtime-tested against the JDK's built-in packages alone — never against JavaFX itself. Your build output was the first genuine full-project compile.

## Errors and fixes

**1. `SalesView.java:977,17` and `:980,17` — `cannot find symbol: variable Toast`**
- **Where:** `showAddDeliveryDialog()`, added in v11.6
- **Cause:** Two `Toast.success(...)` / `Toast.error(...)` calls were left unqualified. `SalesView.java` never has a plain `import com.kaziflow.utils.Toast;` — every other call site in this file uses the fully-qualified `com.kaziflow.utils.Toast...`, and these two were missed when the delivery dialog was written.
- **Fix:** Fully-qualified both calls to match the file's existing convention. Swept the rest of the file for the same pattern — no other instances found.

**2. `DashboardView.java:362,14` and `:373,18` — `cannot find symbol: class Sale`**
- **Where:** `showDayDrillThrough()`, added in v11 (dashboard drill-through)
- **Cause:** Uses `List<Sale> daySales` and `for (Sale s : daySales)`, but `com.kaziflow.models.Sale` was never imported — only `com.kaziflow.models.Product` was.
- **Fix:** Added `import com.kaziflow.models.Sale;`.

**3. `StockTakeView.java:44,9` — `cannot find symbol: class Scene`**
- **Where:** `open()`, added in v11.1 (stock-take module)
- **Cause:** `Scene scene = new javafx.scene.Scene(root, 720, 560);` — the constructor call was fully qualified but the variable's declared type on the left was left bare, with no `javafx.scene.Scene` import anywhere in the file.
- **Fix:** Fully-qualified the declared type too: `javafx.scene.Scene scene = new javafx.scene.Scene(...)`.

## What this confirms about the verification gap

All three were the exact same category of mistake: a class referenced without being either imported or fully qualified, in code written and reviewed without a working compiler for JavaFX code. Every prior manual review pass (balance checks, cross-referencing DB columns, array-index checks) was real and caught real issues, but none of those checks can catch "this identifier isn't actually resolvable" — that specifically requires a compiler, which wasn't available for any JavaFX-dependent file until now.

**Swept the whole project for the same two failure patterns** (bare class name never imported anywhere; declared-type-bare-but-constructor-qualified) using a script — no further instances of either found. That doesn't guarantee there are no other compile errors of a *different* kind still lurking (unresolvable in this sandbox without JavaFX), but it means these specific two mistakes weren't repeated elsewhere.
