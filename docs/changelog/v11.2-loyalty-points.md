# v11.2 — Loyalty Points Redemption

**Task:** Phase 10E, item 4/6.

## Found while starting this: the POS customer dropdown was decorative
- **Where:** `src/main/java/com/kaziflow/views/SalesView.java`
- **Problem:** The customer combo at POS only ever offered "Walk-in Customer" and was never read — `completeSale()` hardcoded every sale's customer to "Walk-in Customer" regardless of what was (theoretically) selected.
- **Fix:** Combo is now populated from `CustomerDAO.findAll()` via `refreshCustomerCombo()`. Selection is tracked in `selectedCustomerId` and actually used in `completeSale()`.

## Loyalty points
- **Where:** `src/main/java/com/kaziflow/dao/CustomerDAO.java`, `src/main/java/com/kaziflow/views/SalesView.java`, `src/main/java/com/kaziflow/App.java`
- New `customers.loyalty_points` column — idempotent `ALTER TABLE` migration (`ensureLoyaltyColumn()`, catches "duplicate column" on repeat runs), registered at startup.
- New `CustomerDAO` methods: `getLoyaltyPoints`, `addLoyaltyPoints`, `redeemLoyaltyPoints` (the latter guarded with `WHERE loyalty_points >= ?` so a stale UI can never push a balance negative).
- **🎁 Redeem button** next to the customer combo — shows the selected customer's balance, lets the cashier redeem points as a cart discount (1 point = KES 1), capped at `min(available points, cart total)`.
- Discount (`redeemedDiscount`) is factored into `updateTotals()`, the numpad's change calculation, and the receipt. Re-capped automatically if the cart shrinks after redemption (can never go negative).
- On sale completion (`applyLoyaltyForCompletedSale`): redeemed points are deducted, new points are earned on the net amount paid (1 point per KES 100) — only for a linked customer, never walk-in.
- Added a **Points** column to the Customers table in `SalesView` so staff can see balances without opening the redeem dialog.
