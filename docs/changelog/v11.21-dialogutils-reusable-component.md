# v11.21 — Reusable DialogUtils Component (Resizable Dialogs, Done the Right Way)

**Context:** asked for resizable dialogs, then correctly caught that fixing 76 individual `Dialog` call sites one-by-one would itself be a violation of the project's stated "build reusable components, avoid repeating yourself" principle. Fixed the actual architectural gap instead of the symptom.

## The real gap

Zero shared dialog-construction utility existed anywhere in this codebase. Every one of ~76 `Dialog`/`TextInputDialog`/`Alert` instantiations across 43 files hand-built its own title/style/width setup from scratch — the same 3-4 lines duplicated everywhere. When "dialogs should be resizable" came up, there was no single place to make that change.

## Fix: `com.kaziflow.utils.DialogUtils`

- `styledDialog(title, width[, height])` — the new standard way to build a dialog going forward: titled, styled, sized, and resizable in one call.
- `makeResizable(Dialog<?> dialog)` — for retrofitting existing dialogs without touching their content-building logic, since JavaFX dialogs default to fixed-size otherwise.

## Applied project-wide, safely

Rather than rewrite each dialog's construction (risky at this scale, and unnecessary for just the resizability fix), applied `DialogUtils.makeResizable(...)` as a **pure line addition** immediately after each dialog's declaration — 24 files for `Dialog<...>` instances, 19 more for `TextInputDialog`/`Alert` (both are `Dialog` subclasses with different constructors, so needed a separate pattern). This is deliberately a different editing approach than the risky in-place *replacement* edits used earlier in this session (see v11.19) — a pure addition can't accidentally delete an adjacent line the way a replacement can, since nothing existing is touched. Verified balanced across all 43 touched files.

Found one self-inflicted redundancy while doing this: the sweep script matched `DialogUtils.java`'s own internal `new Dialog<>()` call and inserted a duplicate `makeResizable()` call right before the one already in `styledDialog()`'s own body. Harmless (idempotent), but removed for tidiness.

## Not done, and deliberately not rushed

Migrating the existing 76 call sites to actually *use* `styledDialog()` (eliminating the duplicated title/style/width boilerplate itself, not just adding resizability) is a real, valuable next step under the same principle — but it's a much bigger, riskier refactor than a pure addition, and wasn't attempted in this pass. Flagged in the project guide as a concrete next architectural investment.
