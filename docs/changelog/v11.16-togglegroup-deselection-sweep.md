# v11.16 — Project-Wide Sweep for the ToggleGroup Deselection Bug

Following up on the same bug class found in `ProfileSelector` (v11.13): JavaFX allows clicking the *already-selected* toggle in a `ToggleGroup` to deselect it entirely, leaving nothing selected. Swept every file in the project using `ToggleGroup` to check for the same gap.

## Real fixes applied

- **`SalesView.java`** — the POS **payment method selector** (Cash/M-Pesa/Card/Bank). This is the most consequential instance found: clicking the already-selected payment method deselected it, leaving nothing visually highlighted while `selectedPayment` silently kept its stale value. Also fixed the product **category filter** toggle in the same file.
- **`SettingsView.java`** — my own **Network mode** radio group (Standalone/Server/Client/Shared) from v11.7, and the pre-existing **Language** selector radio group. Both could be clicked down to no mode/language selected.
- **`DashboardView.java`** — found something different here: the Daily/Weekly/Monthly toggle buttons in the toolbar had **no listener attached at all** — not even the deselection bug, just fully decorative dead UI. Since v11's dashboard work already built real date-range filtering infrastructure, wired these up as genuine quick-filter shortcuts (Daily → today, Weekly → last 7 days, Monthly → last 30 days) instead of leaving them non-functional, and added the same deselection guard.
- **`GymView.java`, `RestaurantView.java`, `WorkshopView.java`, `LaundryView.java`** — all pre-existing (predate this session) status/category filter tabs with the same gap. Fixed identically.

## Already correct, no fix needed

- **`BatchView.java`**, **`DeniView.java`** — both already had the correct guard pattern in place. Good confirmation the bug wasn't universal, just present in about half the files that used this pattern.

## Verification

Wrote a small script to cross-check every file containing `ToggleGroup` against whether it also registers a `selectedToggleProperty()` listener, confirming every group in the project now has one. (Note: this check counts listener registrations, not specifically "guard" listeners — a couple of files also have a separate, pre-existing *functional* listener on the same property, e.g. `RestaurantView`'s menu-reload-on-category-change — those are unrelated to this fix and were already there.)
