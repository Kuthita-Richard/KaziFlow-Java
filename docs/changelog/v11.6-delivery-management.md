# v11.6 — Delivery Management (Phase 10B)

**Design decision confirmed via research on real Kenyan delivery pricing:** blend a flat per-km rate (the common baseline) with fixed-price overrides for named/frequent locations (mirroring real courier zone pricing), plus an optional per-kg surcharge since weight is a real factor alongside distance. A named location's override always wins over the calculated per-km price.

## New module: `delivery`
- **Where:** new `src/main/java/com/kaziflow/dao/DeliveryDAO.java`, new `src/main/java/com/kaziflow/views/DeliveryView.java`, new `src/main/java/com/kaziflow/modules/core/DeliveryModule.java`, `src/main/java/com/kaziflow/modules/ModuleRegistry.java`, `src/main/java/com/kaziflow/modules/IndustryProfile.java`, i18n property files
- New tables: `delivery_locations` (name, distance_km, nullable override_price), `deliveries` (customer, phone, location, distance, weight, charge, rider, status, nullable `sale_id` link).
- `calculateCharge(overridePrice, distanceKm, weightKg)` — override wins if set, otherwise `distance × rate_per_km + weight × rate_per_kg`.
- `DeliveryView` — 3 tabs: Deliveries (assign rider / mark delivered / cancel), Named Locations (add/delete, with override pricing), Pricing (business-wide per-km and per-kg rate settings).
- Added `"delivery"` to the module list of **all 20 product-selling industry profiles** (every profile that already had `"sales"`) via the shared `"deni","quotations"` anchor point in each profile's module list.

## POS checkout integration
- **Where:** `src/main/java/com/kaziflow/models/Sale.java`, `src/main/java/com/kaziflow/dao/SaleDAO.java`, `src/main/java/com/kaziflow/views/SalesView.java`, `src/main/java/com/kaziflow/App.java`
- New `sales.delivery_charge` column (idempotent `ALTER TABLE`, created by `DeliveryDAO.ensureTables()`), new `Sale.deliveryCharge` field, persisted in `SaleDAO.save()` and read back in `mapRow()` (tolerant of pre-migration rows via a local try/catch).
- New **🚚 Delivery** button next to Redeem in the POS header — pick a named location (auto-fills distance + price) or enter a custom distance/weight, with a live charge preview before confirming.
- Delivery charge is additive into `updateTotals()` and `completeSale()` (the mirror image of the loyalty discount, which is subtractive) and shown inline on the total label.
- On successful sale (`createDeliveryRecordIfNeeded()`, called from both the cash and M-Pesa success paths), the actual `deliveries` row is created and linked to the new sale's `id` — not just a charge on the receipt, a real trackable delivery ready for rider assignment.
